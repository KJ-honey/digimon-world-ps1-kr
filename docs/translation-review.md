# 번역 초안과 검수 도구

기준일: 2026-09-28. 이번 작업은 **문구 수정과 검수**이며 ISO·폰트·삽입 엔진은 수정하지 않았다.
원문보다 길어도 저장한다. 단어를 줄이거나 띄어쓰기를 없애서 슬롯에 맞추지 않는다.
게임의 relocation·버퍼·화면 배치 검증은 이 문구 작업과 별개다.

## 실행

```sh
python3 tools/translation_review.py serve --open
# http://127.0.0.1:8770/
```

추출 기준을 처음 만들거나 원본과 다시 대조하려면:

```sh
python3 tools/translation_review.py prepare
python3 tools/translation_review.py report
```

`prepare`는 두 불변 ISO의 전체 SHA-256을 검사하고 기존 DG 소비자 파서로 다시 읽는다.
기존 검수 데이터는 덮어쓰지 않는다. 기준이 달라지면 중단한다. 기존 분석 환경의
의존성(`requirements-analysis.txt`)을 이용하며 브라우저 라이브러리·외부 API는 필요 없다.
`prepare`는 번역문을 생성하거나 재생성하지 않는다.

## 검수 흐름

1. 기본 목록은 **수정된 문장**이다. 일본어 원문·기존 번역·수정 초안을 세 열로 함께 본다.
2. 수정 근거와 차이를 읽고, 필요하면 세 번째 열에서 직접 고친다.
3. **문구 승인 후 다음** 또는 **보류 후 다음**으로 처리한다. 불확실한 점은 메모에 남긴다.
4. 수정한 문장을 다른 항목으로 이동하면 초안으로 저장한다. 승인과 자동 저장은 구분된다.
5. 필터에서 미검수·승인·보류·번역 작업 전·확인된 DG 전체를 선택한다.
   원문·기존 번역·새 번역·수정 근거·메모·ID를 검색할 수 있다.

`⌘/Ctrl+Enter`는 승인 후 다음, `⌘/Ctrl+S`는 초안 저장, `Alt+←/→`는 이동,
`/`는 검색이다. 같은 script의 앞뒤 두 항목을 열어 문맥을 확인할 수 있다.
**파일 순서가 실제 대화·분기 순서라는 뜻은 아니다.** 화자가 확정되지 않은 항목을
임의의 디지몬으로 단정하지 않았다.

수정 중인 내용은 브라우저에도 임시 보관된다. 파일 저장 상태를 별도로 표시하며,
실패하면 입력을 유지한다. 마지막 문장으로 다시 돌아온다.
**저장된 초안으로 되돌리기**는 아직 저장하지 않은 편집을 버리고 마지막 파일 저장본을 연다.
**기존 번역 유지**는 원래 번역으로 돌아가기로 한 검수 결정을 기록한다.
이전 문구·메모·승인 상태는 변경 이력에 남는다. 다중 창의 오래된 revision 저장은 거부한다.
서버와 CLI import는 파일 잠금을 공유하여 다른 문장의 검수 결정을 덮어쓰지 않는다.

줄바꿈은 기존 `0D00` 경계에 대응한다. 문장 끝의 마지막 `0D00`은 편집기에서 숨겨
자동 보존하므로 마지막 빈 줄을 직접 넣을 필요가 없다. 그 밖의 보호 토큰은 `⟦0107⟧`,
`⟦03000000⟧`, `⟦G:816F⟧` 형태다. `03`의 4바이트 인자를 글자로 해석하지 않는다.
토큰·인자·순서를 잃으면 저장을 거부한다. 글자 수는 제한하지 않지만 줄/제어의 개편은
별도 레이아웃 작업이다. 이 화면의 줄 배치는 실제 게임 화면 검증이 아니다.

1,887개는 **사용자 검수 전 초안 기록**이다. 실제 문구가 바뀐 1,857개와 기존 문구 그대로인
30개(짧은 감탄·침묵 등)를 구분한다. 후자는 사용자 승인이나 `unchanged` 결정이 아니다.
전체 번역 완료가 아니다. 나머지 **2,730개에는 아직 초안 검수 기록이 없다.**
script 0/149에서 남긴 18개는 일반 라벨 5개와
워프·진화·시간 진행 등 디버그 성격으로 보이는 문맥 13개이며, 실행 여부나 제외를 확정하지 않았다.
다음 범위는 script 76 이후의 미작성 단위다. 이미 작성된 마을·상점 범위는 건너뛴다.
이전 검색 후보 3,381개와 다른 모듈은 이 4,617개에 더해 전체 작업량으로 계산하지 않는다.

주요 수정은 발화 방향·행동·시제·존비어·띄어쓰기다. 예를 들면:

- `0059c0`: 할배몬이 주인공에 대해 묻는 문장을 자기 이야기를 들어 달라는 오역에서 복원.
- `004a66`: `チビ`를 ‘구두쇠’에서 ‘꼬맹이’로 수정.
- `064c22/064dcc/064ef2`: 일본어 코드가 남아 깨진 고기 획득 메시지의 내용·수량 복원.
- `063a74`: 장사에 능한 다른 이가 **없다**는 문장을 **있다**고 뒤집은 오역 수정.
- `06178a`: 팩토리얼 타운 귀환 여부 질문 복원.
- `06230c/062350`: 적대적 화자의 원문 존댓말 복원.
- `065a8c`: 반복 토벌을 연례행사에 비유한 주인공의 농담 복원.

일본어 말투·존댓말/반말 구분·올바른 띄어쓰기는 사용자 확정 원칙이다.
2026-09-28 사용자가 `だか` 말투를 **노인 어투가 아닌 천진난만한 느낌**으로 보정했다.
해당 판매/교환 초안 13개를 고치고 관련 상점 대사에도 반영했다.
예: `정말 내게 주는 겐가?` → `정말 나 주는 거야?`.
다른 화자의 노인 말투나 일반 접속사 `だから`에는 이 기준을 확장하지 않는다.
`アル→~다 해`, `へこへこ→헤코헤코`, 특정 인물의 하게체, 헤비 딸기·그레이트 캐니언·
해안 동굴 등의 새 표현은 **제안**이며 승인된 전역 용어표가 아니다.
`work/translation/style-decisions.json`에 범위와 상태를 기록했다.
기존 이름은 기본적으로 유지하고 변경 제안은 문장별 근거에 표시한다.
기계적인 일괄 띄어쓰기·단어 치환으로 번역을 생성하지 않았다.
상점 아르바이트는 원문·기존 번역이 같은 지정 ID를 함께 읽고 문구를 작성한 뒤 각 ID에 저장했다.
숫자·가격 변경 방향은 404개 모두 원문과 대조했다. 고객의 말투는 각각 작성했다.

추가 검수 제안에는 닌자몬의 `でち`, 고스몬의 이름 말버릇, 씨라몬의 말장난,
`제사용 술/저택 열쇠` 명칭이 있다. 저택 수수께끼 `バカ`에서 탁점을 빼면 `ハカ(墓)`가 되는
표현은 `무덤덤에서 덤 하나를 뺀 곳`으로 제안했다(`0260f6/0261cc`).
진행에 영향을 주는 단서라 원문·이전 번역·수정 근거를 함께 검수해야 한다.
`01f0e8`의 `べんきょうしまっせ`는 할인이라는 상인 관용구 해석을 제안했으나,
전투 외침의 화자/소비 문맥에 따라 재확인할 항목으로 기록했다.

## 보존과 후속 입력

| 로컬 파일 | 역할 |
| --- | --- |
| `work/translation/baseline.json` | 두 ISO 해시, 검수 문자표 해시, ID, 논리 파일 offset, 원문·기존 번역, raw bytes, 소비자 토큰 |
| `work/translation/reviews.json` | 수정 문구·사유·메모·문구 해시·작성자·revision·이전 결정 이력 |
| `work/translation/style-decisions.json` | 사용자 원칙과 아직 승인되지 않은 말투·용어 제안 |
| `work/translation/issues.json` | 원문/기존 번역의 제어열 불일치 9개 |
| `work/translation/checkpoint-20260928.json` | 초기 363개 초안의 전체 검수 백업 |
| `work/translation/checkpoint-20260928-full-work-001.json` | 후속 1,887개 전체 검수 백업 |
| `work/translation/progress-20260928-full-work-001.json` | script별 진행 수와 미작성 범위 |
| `work/translation/verification-full-work-001.json` | 현재 초안의 보호 토큰·한글·숫자·테스트 검사 |
| `work/translation/batches/` | 개별 작성 TSV와 저장·검사 보조 스크립트. 현재 문구의 기준은 reviews.json |

브라우저의 **검수 백업**은 기준 자료·현재 결정·이력·용어/문제 기록을 함께 JSON으로 내려받는다.
`work/`는 Git 제외 대상이므로 별도 백업한다. 최초 TSV/JSON 묶음은 초안 작성 기록이고,
수정 이후의 기준 문구는 항상 `reviews.json`이다. import는 기존 결정을 덮어쓰지 않는다.

원문과 기존 번역의 제어열이 다른 단위는 9개다. `063b2c`의 주인공 이름 삽입과
`01e28e/01e2d0`의 화자명 색상 토큰을 초안에서 원문과 동일한 토큰열로 복원했다. 단순 문구 확장과 구분해
`source_controls_restored_in_draft=true`를 남겼다. 원문과도 일치하지 않는 새 제어열은 거부한다.
이 구조 복원의 게임 적용은 미검증이다. 특수 글리프와 일본어 미확정 코드도 원문에 보존한다.

`accepted`는 **이 문구에 대한 사용자 승인**만 뜻한다. 모든 레코드에
`product_eligible=false`, `layout_verified=false`, `runtime_verified=false`를 유지한다.
이 도구에는 인코더·ISO 쓰기·제품 빌드 manifest 내보내기 기능이 없다.
원문 바이트 길이보다 긴 문장이나 ASCII 문장부호의 최종 인코딩·레이아웃·공간 확보는 후속 작업이다.
초안의 한글 음절에는 KS X 1001 2,350자 밖의 글자가 없음을 확인했지만,
이는 모든 기호의 인코딩 또는 실제 화면 표시가 검증됐다는 뜻이 아니다.

## 검증

`python3 -m unittest discover -s tools -p 'test_translation_review.py'`의 8개 테스트로
긴 문장 저장·보호 토큰 손실/변경/순서 오류·revision 충돌·이력 보존·원문 기준 불일치·
보조 작성자의 승인 금지·원문 이름 토큰 복원·4바이트 제어 인자 표시를 확인한다.
`prepare` 재실행으로 전체 4,617개 기준 자료가 불변 ISO에서 동일하게 재생성됨을 확인했다.
현재 저장소의 Python 테스트 51개가 통과했다.
`node --test tools/test_translation_editor.js`의 2개 검사로 편집기 표시/저장 왕복을 확인한다.
원본 4,617개와 초안 1,887개가 모두 같은 문자열로 돌아오며, 연속된 마지막 빈 줄도 보존한다.
Node는 이 추가 검사의 실행에만 필요하고 검수 서버에는 필요하지 않다.

Safari의 별도 `work/translation-ui-qa/` 3문장 사본에서 긴 문장·메모 저장,
승인 후 다음 이동, 보류 후 다음 이동, 토큰 누락 저장 거부, 새로고침 후 마지막 항목 복원을 확인했다.
시험용 승인 기록은 실제 번역 초안과 분리했다. 실제 초안의 사용자 문구 승인 기록은 0개다.
현재 서버 API에서도 1,887개 초안이 조회됨을 확인했다.
