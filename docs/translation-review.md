# 번역 초안과 검수 도구

기준일: 2026-09-28. 이번 작업은 **문구 수정과 검수**이며 ISO·폰트·삽입 엔진은 수정하지 않았다.
원문보다 길어도 저장한다. 단어를 줄이거나 띄어쓰기를 없애서 슬롯에 맞추지 않는다.
게임의 relocation·버퍼·화면 배치 검증은 이 문구 작업과 별개다.

## 실행

```sh
python3 tools/translation_review.py serve --open
# http://127.0.0.1:8770/
```

추출 기준을 처음 만들거나 원본과 다시 대조하려면:

```sh
python3 tools/translation_review.py prepare
python3 tools/translation_review.py report
```

`prepare`는 두 불변 ISO의 전체 SHA-256을 검사하고 기존 DG 소비자 파서로 다시 읽는다.
기존 검수 데이터는 덮어쓰지 않는다. 기준이 달라지면 중단한다. 기존 분석 환경의
의존성(`requirements-analysis.txt`)을 이용하며 브라우저 라이브러리·외부 API는 필요 없다.
`prepare`는 번역문을 생성하거나 재생성하지 않는다.

## 검수 흐름

1. 기본 목록은 **전체 관리 항목**이다. 종류에서 대사·지명·아이템명·아이템 설명·디지몬 이름을 고르고,
   일본어 원문·기존 번역·수정 초안을 세 열로 함께 본다.
2. 수정 근거와 차이를 읽고, 필요하면 세 번째 열에서 직접 고친다.
3. **문구 승인 후 다음** 또는 **보류 후 다음**으로 처리한다. 불확실한 점은 메모에 남긴다.
4. 수정한 문장을 다른 항목으로 이동하면 초안으로 저장한다. 승인과 자동 저장은 구분된다.
5. 필터에서 수정 항목·미검수·승인·보류·번역 작업 전·전체 관리 항목을 선택한다.
   원문·기존 번역·새 번역·수정 근거·메모·ID를 검색할 수 있다.

`⌘/Ctrl+Enter`는 승인 후 다음, `⌘/Ctrl+S`는 초안 저장, `Alt+←/→`는 이동,
`/`는 검색이다. 같은 script의 앞뒤 두 항목을 열어 문맥을 확인할 수 있다.
**파일 순서가 실제 대화·분기 순서라는 뜻은 아니다.** 화자가 확정되지 않은 항목을
임의의 디지몬으로 단정하지 않았다.

수정 중인 내용은 브라우저에도 임시 보관된다. 파일 저장 상태를 별도로 표시하며,
실패하면 입력을 유지한다. 마지막 문장으로 다시 돌아온다.
**저장된 초안으로 되돌리기**는 아직 저장하지 않은 편집을 버리고 마지막 파일 저장본을 연다.
**기존 번역 유지**는 원래 번역으로 돌아가기로 한 검수 결정을 기록한다.
이전 문구·메모·승인 상태는 변경 이력에 남는다. 다중 창의 오래된 revision 저장은 거부한다.
서버와 CLI import는 파일 잠금을 공유하여 다른 문장의 검수 결정을 덮어쓰지 않는다.

줄바꿈은 기존 `0D00` 경계에 대응한다. 문장 끝의 마지막 `0D00`은 편집기에서 숨겨
자동 보존하므로 마지막 빈 줄을 직접 넣을 필요가 없다. 그 밖의 보호 토큰은 `⟦0107⟧`,
`⟦03000000⟧`, `⟦G:816F⟧` 형태다. `03`의 4바이트 인자를 글자로 해석하지 않는다.
토큰·인자·순서를 잃으면 저장을 거부한다. 글자 수는 제한하지 않지만 줄/제어의 개편은
별도 레이아웃 작업이다. 이 화면의 줄 배치는 실제 게임 화면 검증이 아니다.

위 줄바꿈/제어 설명은 DG 대사에 해당한다. **지명·아이템명·설명·디지몬 이름**은 별도 한 줄 문자열로
편집하며 DG 종료코드를 붙이지 않는다. `prepare`는 이제 대사와 명칭 테이블을 모두 준비한다.
기존 대사 자료를 유지한 채 추가하려면 `python3 tools/translation_review.py prepare-catalog`를
실행하고 서버를 다시 시작한다. 추가 506개와 원본 좌표·미해결 범위는
[지명·아이템 관리](translation-catalog.md)에 기록했다. 이들 문구의 기준은
`work/translation/catalog/reviews.json`이며 Git에 보존한다. 통합 검수 백업은 format 2의
`families` 배열에 각 기준 자료·검수 이력을 함께 담는다.

브라우저의 **검수 백업**은 기준 자료·현재 결정·이력·용어/문제 기록을 함께 JSON으로 내려받는다.
`work/translation/reviews.json`, `style-decisions.json`, `issues.json`은 Git 추적 대상이다.
`reviews.json`에는 이전 revision의 문구·사유·작성자·시각도 보존한다. 추출 기준 자료인
`baseline.json`과 ISO·빌드·QA 산출물은 계속 Git에서 제외한다. 최초 TSV/JSON 묶음은 초안 작성 기록이고,
수정 이후의 기준 문구는 항상 `reviews.json`이다. import는 기존 결정을 덮어쓰지 않는다.

2026-09-28 폭 기준 정정의 복구 지점:

- `50d70e3`: 168px 조정 완료 상태와 그 이전 수정 이력을 처음 Git에 보존.
- `0139d0e`: 168px 조정 전 4,617개 문구를 전부 복구한 번역 스냅샷. 168px 시기의
  변경도 각 항목의 `history`에 남는다. 이 스냅샷에는 252px 초과 219개가 있으므로
  그대로 제품 빌드하는 기준은 아니다.
- 현재 `reviews.json`: 252px에 맞춰 219개를 배치한 상태. 218개는 문구를 유지한
  줄바꿈·공백 배치, 신문 1개는 사용자 승인에 따라 기존 줄 수 안에 축약했다.

과거 문구 확인: `git show 0139d0e:work/translation/reviews.json`.
이후 번역 수정도 이 파일의 diff를 검토하고 커밋한다. 번역은 재생성 가능한 임시
산출물로 취급하지 않는다. 복구할 때는 함께 대응하는 `tools/dg_line_reflows.json`의
보호 토큰 허용 기록도 대조하며, 빌드 검사를 우회하지 않는다.

원문과 기존 번역의 제어열이 다른 9개를 모두 초안에서 복원했다. 이름·화자명 색상 등의
복원을 단순 문구 확장과 구분해 `source_controls_restored_in_draft=true`를 남겼다.
`06f8a2`는 기존 번역에서 버튼 글리프도 빠져 있었다. 이 경우는 **전체 토큰열이 원문과 정확히
일치하고, 기존 글리프를 순서대로 모두 유지할 때만** 복원을 허용한다.
`source_tokens_restored_in_draft`는 전체 토큰 복원을 기록한다. 임의 버튼 변경·삭제·중복은 거부한다.
이 구조 복원의 게임 적용은 미검증이다. 특수 글리프와 일본어 미확정 코드도 원문에 보존한다.

`accepted`는 **이 문구에 대한 사용자 승인**만 뜻한다. 모든 레코드에
`product_eligible=false`, `layout_verified=false`, `runtime_verified=false`를 유지한다.
이 도구에는 인코더·ISO 쓰기·제품 빌드 manifest 내보내기 기능이 없다.
원문 바이트 길이보다 긴 문장이나 ASCII 문장부호의 최종 인코딩·레이아웃·공간 확보는 후속 작업이다.
초안의 한글 음절에는 KS X 1001 2,350자 밖의 글자가 없음을 확인했지만,
이는 모든 기호의 인코딩 또는 실제 화면 표시가 검증됐다는 뜻이 아니다.
