# 대사 공백과 연출 배치

2026-09-28, 문구 변경 `spacing-001`, 정확한 6px 출력 `spacing-003`. 사용자 요청에 따라 현재 DG 번역 초안에 적용했다.

| 번역 파일 표기 | 게임 bytes | 동작 |
| --- | --- | --- |
| 일반 공백 U+0020 | `0F 00` | 기존 DG 반칸 명령, 논리 좌표 +6px |
| 전각 공백 U+3000 `　` | `81 40` | 기존 한 칸 공백, +12px |

둘 다 **2바이트**다. `,`·`!`를 포함한 일반 글자의 전진 폭은 12px 그대로다.
일반 EXE 문자열·이름 문자표에는 `0F00` alias를 추가하지 않는다. DG 전용 인코더에서만
사용한다. `dg_build.py`의 기존 고정 슬롯 정책은 유지한다.

## 확인한 실제 동작과 사용자 결정

원본 DG 소비자 RAM `0x800F4200`은 `0F00`을 2바이트 단위로 행 버퍼에 복사한다.
행 렌더러 RAM `0x800F34E4`의 `0x800F3738..378C`는 6px 공백을 처리한다.
EXE 논리 파일 offset은 각각 `0x64200`, `0x634E4`, `0x63738..378C`다.
일본어·한국어 EXE 양쪽에서 반칸/전각/반칸 2개/문장부호/색 제어 혼합을 CPU 실행했다.

그러나 glyph 업로더 RAM `0x800A5AB4`는 X를 4로 나누어 VRAM word 좌표로 바꾼다.
따라서 반칸 뒤 글자는 논리 좌표보다 0 또는 2px 왼쪽에 표시되어 공백 간격이
**실제로는 4·8px로 번갈아 나타난다**. 초기의 ‘실제 픽셀도 언제나 정확히 6px’ 가설은
첫 게임 화면의 15개 glyph가 예상보다 2px 왼쪽에 있었으므로 폐기했다.

사용자는 처음에는 정확한 반칸이 아니어도 된다고 했으나, **4·8px 교대라는 설명을 듣고
“이건 6픽셀 고정으로 수정해야겠다.”로 요구를 변경했다.** 최종 요구는 실제 6px 고정이다.
이전 `spacing-001`은 비교 증거이며 현재 테스트 이미지는 `spacing-003`이다.

### 정확한 픽셀 출력

`tools/dg_pixel_row.s`는 원래 DG 행 파서·색 제어·탭·글꼴 공급을 그대로 호출한다.
변환된 4bpp 글리프를 256×12 픽셀의 행 버퍼에 배치한 뒤 한 번 전송한다.
일반 공백 +6px와 전각 +12px가 실제 픽셀 좌표로 이어지므로 반칸 뒤의 연속 글자나
공백 삭제 후 붙은 구두점이 앞 글자의 끝을 덮지 않는다.

- DG 행 진입 RAM `0x800F34E4`, 종료 `0x800F384C`를 감싸고, 내부 공백 지우기 4곳과
  글리프 업로드 `0x800A5B24`를 연결한다. 업로드는 저장된 호출자 주소가 DG일 때만
  행 버퍼로 복사한다. EXE/UI/이름 등의 일반 글리프 업로드는 원래 함수로 전달한다.
- 행 시작 X는 두 확인된 호출 지점과 좌표 함수 `0x800F2FB8` 기준 0 또는 128이다.
  원래 글리프 X<244 제한은 유지한다. 전송 구간은 시작 열에서 최대 256px까지다.
- 코드는 확장 폰트 공급자가 이미 회수한 EXE 논리 offset `0x9D714` / RAM `0x8012D714`에
  716 bytes로 배치한다. 원본 글꼴 소비자는 압축 공급자로 대체되어 있다.
  글꼴 데이터·사전·scratch와 겹치지 않으며 최종 sector 계획에서 단일 writer로 합친다.
- 임시 스택은 1,616 bytes(행 픽셀 1,536 bytes 포함), 상주 RAM 증가는 없다.
  원래 행 함수와 글리프 함수의 프레임·callee-saved 레지스터는 복원한다.
  전송 후 `0x80094774`의 DrawSync(0)를 기다려 GPU가 스택 데이터를 읽기 전에
  버퍼가 사라지는 일을 막는다.
- LLVM MIPS I 조립/역조립 왕복, Capstone 독립 디코딩 및 load/branch delay 검사를 통과한다.
  후크 원본 bytes와 최종 branch target을 검사한다.
- 정확한 공백 빌드는 `--expand-font`가 필요하다. 공백 명령을 사용하면서 이 옵션을
  생략하면 빌드를 거부하여 예전 4·8px 결과를 새 테스트판으로 오인하지 않게 한다.

## 번역 수정

- 확인된 DG 4,617개를 검사하여 현재 문구 2,558개를 수정했다.
- 쉼표·느낌표(`, ! 、 ， ！`) 바로 뒤 공백 1,667곳을 제거했다. 최종 잔여 0곳.
  다른 문장부호까지 임의로 전역 삭제하지 않았다.
- 원문 행의 앞 공백을 전각으로 복원했다. 색 제어 앞뒤 공백 위치도 보존한다.
  `「` 뒤 첫 글자와 다음 줄의 전각 한 칸 들여쓰기가 같은 열에 놓인다.
- 원문에 `「」`가 없는 **1,020개**를 배치 관점에서 대조했고 **440개**를 수정했다.
  간판·훈련/낚시 안내·엔딩·수상 안내의 들여쓰기와 빈 줄, 매출·대회 안내의 구획을 복원했다.
  ‘괄호 없음’을 실제 연출 장면 도달 증거로 취급하지 않는다.
- 가격표 36행을 한국어 띄어쓰기 폭을 반영해 원문 숫자 열에 맞췄다.
  `08aa6a`의 스테이크 메뉴 3행은 현재 한국어 이름과 겹치지 않게 숫자 열을 원문보다
  12px 오른쪽으로 함께 이동했다. 해당 식당의 실제 화면 검증은 남는다.
- script 224의 실적표 114개는 전각 공백 배열을 유지했다.
- `01013c`는 원문의 경고 간판 형식에 맞게
  `경고·무모한 자에겐 포격 준비가 되어 있다.`로 개별 대조 수정했다.

모든 항목에서 이전 초안의 보호 토큰·인자·순서를 보존했다. 원문과 기존 패치의 제어열이
다른 9개는 이번에 임의로 해결하지 않았다. 변경 전 전체 백업, revision 이력, 원문·전후
문구·사유는 `work/spacing/applied-001/`와 `work/spacing/final-layout-review.json`에 있다.
현재 최종 문구는 `work/translation/reviews.json`이며 기존 승인 상태를 새 승인으로 만들지 않았다.
